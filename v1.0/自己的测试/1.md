Side Question: 如果我现在要自己测试一下 做一个第一次系统级联调，我的步骤是什么

进行第一次系统级联调，建议按照 **“硬件接线 $\rightarrow$ 模拟器配置 $\rightarrow$ 固件烧录 $\rightarrow$ 本地调度日志验证 $\rightarrow$ MQTT 云端控制闭环”** 5 个步骤推进：

---

### 第一步：硬件接线与从站准备

1. **RS485 转接板与 ESP32-S3 接线**：
   - `DI`（发送） $\rightarrow$ **GPIO 4**
   - `RO`（接收） $\rightarrow$ **GPIO 5**
   - `DE / RE`（流控使能） $\rightarrow$ 并联后接 **GPIO 6**
   - `VCC / GND` $\rightarrow$ 3.3V / 5V 与 GND
2. **连接 Modbus 从站**：
   - 将 RS485 的 `A+ / B-` 差分线连接到实际从站设备（或用 USB-to-RS485 连接电脑打开 **Modbus Slave 模拟器**）。
   - 从站参数配置：
     - **从站地址**：`2`（或与 `config_default.h` 中的 `slave_id` 一致）
     - **波特率**：`115200`，`8-N-1`
     - **保持寄存器（Holding Registers）**：在地址 `0x0010`（十进制 16）处填入模拟原始值（如 `255`）。

---

### 第二步：网络与 MQTT 参数确认

检查工程中的 WiFi 与 MQTT 配置（如 [`WIFI_sta.h`](file:///d:/1-4ESP32/Industrial%20Gateway/v1.0/components/BSP/WIFI/WIFI_sta.h) 和 [`MQTT_CLIENT_APP.h`](file:///d:/1-4ESP32/Industrial%20Gateway/v1.0/components/Middlewares/MQTT/MQTT_CLIENT_APP.h)）：
- 确认 WiFi 热点 SSID 与密码与您当前的测试路由器匹配。
- 确认 EMQX / MQTT Broker 的 IP 地址、端口与网关处于同一局域网或公网可达。

---

### 第三步：固件烧录与启动监控

在 PowerShell 中执行烧录并打开串口监视器（替换 `COMx` 为您的实际端口）：
```powershell
. D:\Espressif\frameworks\esp-idf-v5.4.4\export.ps1
idf.py -p COMx flash monitor
```

---

### 第四步：观察系统启动与本地调度日志

按顺序核对串口输出的 5 个关键阶段日志：

1. **系统引导与服务就绪**：
   - 看到 `LED_task` 启动，板载 LED 以 500ms 周期闪烁。
   - `CONFIG_MGR`: 打印加载成功及解析出的设备列表（如 `temperature_sensor`）。
   - `MODBUS_MASTER`: 打印 `Modbus Master 通用协议栈初始化成功 (波特率: 115200)`。
   - `DEV_SCHEDULER`: 打印 `===== Modbus Scheduler 调度器任务已启动 =====`。
2. **周期性数据采集（上行链路）**：
   - **通信正常时**：调度器每隔 `period` 毫秒打印：
     ```text
     [DEV_SCHEDULER] 采集成功 -> 设备 [temperature_sensor] (ID=2, 寄存器=0x0010, 原始值=255)
     [DATA_PROCESS_STUB] 设备 [temperature_sensor] 数据处理 -> 物理量: 25.50 (原始值: 255, 倍率: 0.10)
     ```
   - **从站断开/异常测试**：拔掉 485 线，观察连续 3 次失败后是否正确触发离线告警：
     ```text
     [DEV_SCHEDULER] ⚠️ 设备 [temperature_sensor] (ID=2) 连续通信失败 3 次，已判定为 [离线]
     ```
3. **网络与 MQTT 连接**：
   - `WIFI_STA`: 获取到 IP。
   - `MQTT_APP`: 连接 EMQX Broker 成功，并打印订阅控制主题成功。

---

### 第五步：云端下行控制联调测试（闭环验证）

1. 在电脑上打开 **MQTTX** 或其他 MQTT 客户端，连接相同的 MQTT Broker。
2. 向控制主题（默认 `MQTT_TOPIC_CONTROL`，如 `/gateway/control`）发布 JSON 指令：
   ```json
   {
     "temp_limit": 38.5,
     "humi_limit": 75.0,
     "status": 1
   }
   ```
3. **观察两个终端的联动**：
   - **ESP32 串口日志**：
     ```text
     [CONTROL] 收到云端控制指令: {"temp_limit":38.5,...}
     [MODBUS_MASTER] 写入温度上限成功: 38.5 ℃ (寄存器值: 385)
     [MODBUS_MASTER] 写入湿度下限成功: 75.0 % (寄存器值: 750)
     [MODBUS_MASTER] 写入设备状态成功: 1
     ```
   - **Modbus Slave 模拟器**：检查对应寄存器 `0x0013`、`0x0014`、`0x0012` 的数值是否已实时被改写为 `385`、`750`、`1`。
