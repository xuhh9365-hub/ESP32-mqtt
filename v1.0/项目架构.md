

目标架构应该体现：

- 硬件驱动和业务逻辑分离
    
- 配置驱动设备
    
- 多设备动态管理
    
- Web只是配置入口，不影响核心逻辑
    
- MQTT和Modbus独立

# 三、核心模块职责定义

## 1. config_manager（配置管理）

职责：

> 管理“设备是什么”

不负责通信。

接口：

```c
config_manager_init();


config_get_device_num();


config_get_device(index,&device);

config_save();
```

数据：

```c
typedef struct
{

char name[32];

uint8_t slave_id;

uint16_t address;

float scale;

uint32_t period;


}device_config_t;
```

---

# 2. device_manager（设备管理）

职责：

> 根据配置生成设备运行实例

流程：

```text
读取配置

↓

发现3个设备

↓

创建3个Modbus任务
```

接口：

```c
device_manager_start();


device_add();


device_remove();
```

---

# 3. modbus_master

职责：

只管协议。

输入：

```c
slave_id

register_address

function_code
```

输出：

```c
raw_data
```

不关心：

- MQTT
    
- Web
    
- 设备名称
    

---

# 4. data_process

职责：

数据加工。

例如：

Modbus读取：

```
1234
```

配置倍率：

```
0.1
```

转换：

```
123.4℃
```

然后生成：

```json
{
"temp":123.4
}
```

---

# 5. mqtt_client

职责：

上传和下发。

上传：

```
ESP32
 |
MQTT Publish
 |
服务器
```

下发：

```
服务器

↓

MQTT

↓

ESP32

↓

Modbus写寄存器
```

# 四、FreeRTOS任务规划

建议：

```text
Task列表


main_task

初始化


     


modbus_task_x

周期采集设备


mqtt_task

上传数据


web_task

处理网页请求


config_task

配置更新


watchdog_task

系统监控

```
